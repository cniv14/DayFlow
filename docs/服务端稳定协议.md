# DayFlow服务端稳定协议 v1

自服务端1.2.0起，将现有v1路由和数据语义作为稳定兼容契约。后续功能优先使用客户端及插件、通用Record扩展字段，不因UI、黄历、Markdown、打卡或助手接入而改变服务端。缺陷与安全修正仍可发布；破坏性变更必须提供独立v2、迁移说明及并行兼容期，不更改v1既有字段含义。

## 不变的接口与身份

保留GET /health、POST /v1/auth/register、/v1/auth/login、/v1/auth/logout、/v1/sync和GET /v1/me，以及已签名更新文件白名单路由。默认端口8765。账号、设备、事项各用自己的标识，密码经scrypt哈希，会话Token只保存哈希并有过期时间。所有记录、变更游标查询和设备列表按登录user_id隔离，不能以传来的用户ID越权。

同步为完整记录CAS：mutation包含record和base_version；服务端返回accepted、conflicts、changes、cursor、has_more。服务器分配version，客户端时钟只作展示，不决定覆盖。完全相同请求重试幂等；过期base_version返回当前记录，由客户端按修订历史判断，不由服务器猜测合并正文。整批输入先验证再事务写入，冲突作为业务结果返回，不清空本地库。

已删除事项保留deleted=true、revision和祖先，不自动硬删删除标记/变更日志。所有客户端保留未知字段；kind沿用task/event/note/inbox/course/project/type，插件的业务语义存扩展字段或普通笔记，不能为每个插件新增服务路由。

## 大记录与资源控制

取消单条64KiB限制。已认证/v1/sync默认没有固定字节配额，DAYFLOW_MAX_SYNC_BYTES=0；管理员可自行按部署资源配置其他值，这不是客户端产品配额。先验证会话，再接收大请求；请求暂存，避免额外保留完整字节数组。JSON解析仍需要单批记录的物理内存。

控制/登录请求仍有2MiB防护、认证尝试限频、连接超时、最多8个活跃请求。同步mutation最多100条；下行最多200条、目标512KiB，第一条再大也单独返回，因此分页不会使大笔记永远无法读取。客户端自适应缩小批次，大文档可独占请求。这些是每批资源调度规则，不是库容量或笔记字数限制。

必须提供Content-Length，不接受Transfer-Encoding；无效JSON、类型和修订/祖先字段拒绝，未知扩展字段原样保留。/health继续protocol=1，新增capabilities和limits；0表示不设产品字节配额。旧客户端小记录调用保持兼容；旧客户端自己的内存与消息限制不由服务端强行解除。

Caddy示例不再强制2MB请求上限。若使用其他反向代理，请自行核对其上传/响应缓冲和超时；客户端失败不能删除本地内容或重置账号。新包需更新一次服务端以获得大记录能力，之后客户端插件不要求频繁服务端升级。

## 部署、备份、回退

Docker数据保存在dayflow-data卷，升级镜像不删除卷。现有表结构沿用，不重建用户数据库。更新前用SQLite在线备份，不直接复制运行中的主.db而遗漏WAL。

```sh
# 容器内使用DAYFLOW_DB，输出文件由用户指定且禁止覆盖已有备份
python backup.py --output /data/backups/dayflow-20261021.db
# 本机
python backup.py --database ./data/dayflow.db --output ./backups/dayflow-20261021.db
```

backup.py包含于服务器ZIP和容器，使用sqlite3.backup。备份与原库含相同私有数据，需妥善保管。恢复时先停服务，备份现有数据库与WAL，再将备份放入数据目录，确认权限后启动；不要在服务运行时覆盖数据库。回退旧版程序可能重新启用旧大小约束，已有大笔记应先备份，不能承诺旧客户端读取无限大记录。

恢复较旧快照可能使客户端游标超出服务器范围；409时停止自动覆盖并保留本地，先导出本地同步文件，再按账号/服务器身份排查，不自动清空库或盲目重置CAS版本。详细身份、消息和错误格式见客户端同步API.md。
