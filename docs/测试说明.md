# DayFlow 0.1.0 首个测试版

这是供功能验证的早期测试版本。先使用测试数据，重要日程请另外保留备份。

## Android

安装 `DayFlow-android.apk`，支持 Android 8.0 及以上。首次安装不要求账号。测试包使用本项目稳定的本机发行证书签名，后续发行应沿用同一证书；不应混装开发环境的 debug APK。

建议先测试：

1. 新建一个没有日期的待办，填写“下个月”等模糊时间。
2. 编辑同一待办，确定日期，检查原事项是否更新。
3. 新建文字笔记、图片笔记，完成和删除任务。
4. 在课表页面导入包内 `课表模板.csv`。`start_date` 是第1周起始日期，`weekday` 为周一1到周日7，`weeks` 支持 all、odd、even。
5. 在设置中启用通知采集，进入系统通知访问授权允许日栖。向 QQ／微信发送包含“会议”“讲座”“报名”或明确时间的测试通知，检查收集箱。
6. 配置兼容 Chat Completions 的 API 根地址、模型、API Key。选择通知，点击“交给 AI 提取”，检查多个事项；截图需要支持视觉输入的模型。提取结果仍为收集箱事项，编辑或转为待办后再使用。
7. 新建带日期事项并勾选通知提醒；测试系统日历导出、系统闹钟入口。系统闹钟须自行检查日期，不适合作为未来日期的自动闹钟。
8. 为未完成任务添加后续阶段任务，完成前置任务，检查后续任务的实际激活时间。
9. 修改壁纸、透明度和动态流光；切入后台、省电模式，检查动画暂停。
10. 添加系统桌面小组件和快捷设置磁贴；试用应用内左下角向右滑快速记录。

## Windows

解压 `DayFlow-windows.zip` 到有写入权限的固定目录，运行 `DayFlow.Widget.exe`。需要 .NET 10 Desktop Runtime。此电脑已有 .NET 10 SDK；其他电脑可从微软安装对应桌面运行时。

标题区域可拖动，右下角可缩放，设置中可关闭置顶、选择壁纸、调整透明度。数据默认保存在 `%LOCALAPPDATA%\DayFlow`，替换应用目录不会清除日程。

## 无服务器文件同步

Android 设置 → 导出 `.dayflow` 文件 → 传到 Windows → 文件同步 → 导入并合并。反向同步同理。连续导入相同文件应不重复创建；两端离线修改同一事项时，应保留冲突副本。删除标记也随文件传递。

## 云端／局域网

此项可跳过。使用 `DayFlow-server.zip` 部署服务器，默认端口8765。Android 和 Windows 使用同一服务器账号，分别生成不同设备 ID。首次勾选注册新账号，后续设备使用登录。

注册用户名为3–40位英文字母、数字、点、横线或下划线，密码10–128个字符。默认仅手动同步，不自动上传历史通知正文给 AI。可以关闭注册或设置服务器邀请码。

## 在线更新

设置中可手动检查，也可开启定期检查。默认使用 GitHub Releases 的签名清单；可改成自建服务器 `/updates/android-update.json` 或 `/updates/windows-update.json`。

首版是0.1.0，发布更高版本前不会显示可更新。每份更新需同时提高版本号与版本代码，并使用同一发行证书和更新签名私钥。Android 安装由系统确认，Windows 确认后下载、验证并重启替换。

本轮已验证编译、更新清单验签、篡改拒绝与包哈希检查。完整的两版本升级、不同设备的系统安装确认和 Windows 文件替换回滚仍需实机测试，不能视为已完成全部更新兼容性验证。
