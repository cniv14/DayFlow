# 在线更新与服务器分发

更新与账号同步独立。客户端不需要登录同步服务器即可从公开更新源检查版本；完全离线模式下不检查。默认自动检查关闭，Android 可开启12小时任务，Windows 可开启6小时检查。网络不可用时保留现有应用与数据。

## 信任链

1. 应用内置 RSA 公钥，清单的 `payload` 以 UTF-8 JSON 编码后进行 Base64。
2. 对原始 payload 字节使用 RSA PKCS#1 v1.5 / SHA-256 签名，放入 `signature`。
3. 客户端先验证签名、平台、长度与版本，再下载包，流式计算 SHA-256。
4. Android 把验证后的 APK 交给系统安装器，系统继续检查 APK 身份与签名；用户确认后安装。
5. Windows 更新辅助程序再次验证签名和包哈希，等待挂件退出，备份将替换的应用文件，再替换并重启。用户数据目录独立保留；替换失败时尝试恢复应用文件，并将错误写入数据目录 `update-error.txt`。

APK 必须沿用原发行证书。`.signing/` 中的私钥和密码不能提交 GitHub、放到更新服务器或包含在发布 ZIP 中。公开仓库只包含验证公钥。若维护者授权 CI 签名，应通过 GitHub Actions Secrets 提供，而不是写入工作流正文。

## 生成更新

构建时安装 `cryptography`，运行 `tools/release_keys.py` 一次建立本机发行身份。修改版本时同时更新 Android `versionCode/versionName`、Windows 版本号、`UpdateFeed.VersionCode`，再构建。

```powershell
python tools/publish_updates.py --key .signing/updates-private.pem --output server/updates --base-url https://calendar.example.com/updates --version 0.1.1 --code 2 --android dist/DayFlow-android.apk --windows dist/DayFlow-windows.zip
```

如果使用 GitHub Release，`--base-url` 改为具体 Release 的下载前缀，例如 `https://github.com/cniv14/DayFlow/releases/download/v0.1.1`，把输出清单和包同时上传到该 Release。

## 配置客户端

默认源是 `https://github.com/cniv14/DayFlow/releases/latest/download/平台-update.json`。自托管时在设置中改为 `https://你的域名/updates/android-update.json` 或 `windows-update.json`；局域网可显式使用 HTTP 私有IP地址。清单签名检查始终开启，不能在设置里关闭。

服务器“发布更新”后，客户端在下一次手动或定期检查时收到提示。当前采用系统调度的定期检查，没有常驻推送连接，也不依赖 Google 推送服务。系统省电策略可能推迟 Android 检查。

原生应用升级需要系统安装或进程重启。当前不提供绕过安装确认的静默安装，也不动态执行远程下发的 DEX 或脚本。服务端升级使用容器重建，具体见服务器部署文档。
