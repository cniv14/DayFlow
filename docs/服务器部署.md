# 可选服务器部署

完全本地使用时无需部署。服务器保存同步记录和账号，不运行 AI 或 OCR 模型。

## 直接运行

需要 Python 3.12+，不需要 pip 安装依赖。

```powershell
cd server
python server.py --host 0.0.0.0 --port 8765 --db dayflow.db
```

同一局域网设备填写 `http://服务器局域网IP:8765`。`http://127.0.0.1:8765` 只指向当前设备自身。防火墙只按需要放行可信局域网网段。

## Docker

```sh
cd server
cp .env.example .env
mkdir -p updates
docker compose up -d --build
```

默认端口仅绑定服务器本机 `127.0.0.1`。局域网访问时在 `.env` 设置 `DAYFLOW_BIND=0.0.0.0`，并限定防火墙范围。可用 `DAYFLOW_PORT` 更改宿主机端口，容器内保持8765。

数据库在持久化卷 `dayflow-data`。备份请使用 SQLite backup API 或停止容器后备份卷，不能只复制运行中的 `.db` 而忽略 WAL 文件。

## 云端 HTTPS

将域名 DNS 指向服务器，在 `.env` 填写 `DAYFLOW_DOMAIN=calendar.example.com`，开放80/443，再执行：

```sh
docker compose --profile cloud up -d --build
```

Caddy 负责 HTTPS，客户端填写 `https://calendar.example.com`。云端不需要把8765直接暴露到公网。首次注册后可将 `DAYFLOW_REGISTRATION=false` 关闭注册，或使用 `DAYFLOW_INVITE_CODE` 限制新账号注册。修改后重新创建容器。

## 账号

用户名区分大小写前先统一为小写，不是邮箱。账号ID由服务器生成，设备ID由客户端生成。密码使用独立随机盐的 scrypt，令牌仅保存 SHA-256 摘要，30天过期，注销可撤销当前令牌。当前没有邮箱验证和找回密码流程。

## 分发更新

将签名清单与安装包放到 `server/updates/`，容器只读挂载。服务器提供：

- `/updates/android-update.json`
- `/updates/windows-update.json`
- `/updates/DayFlow-android.apk`
- `/updates/DayFlow-windows.zip`

客户端必须信任内置公钥验证的签名，因此其他服务器不能随意替换安装包。发布脚本与密钥说明见 `更新机制.md`。接口不提供远程匿名上传；更新由服务器维护者本地发布。

## 更新服务端

服务端源文件与 Dockerfile 一并提供。安装新版本前备份数据库，然后用新源码重新构建：

```sh
docker compose up -d --build
```

这会重建应用容器，数据卷保留。它不是进程内热替换；首版不自动拉取或执行服务器上的新代码。未来数据库结构变更必须提供迁移和回滚方案。
